Actor mapping: alice -> validCustomer, bob -> legacyCustomer,
charlie -> stranger, company -> treasury.

credentialStatus "valid" requires ALL of: matching subject, matching trusted
issuer, matching credential type (case-insensitive), exists + accepted flag,
a concrete ledger entry id, and not expired. An unaccepted/expired/incomplete
read raises instead of reporting valid. A missing credential is "none";
"revoked" is only used when setup recorded a validated CredentialDelete.

Payments: validCustomer sends its real CredentialIDs; legacy/stranger never
send CredentialIDs. Only validated tesSUCCESS = allowed, only validated
tecNO_PERMISSION = blocked; anything else (incl. timeouts) is inconclusive and
keeps its hash/code. Reviewed repair is preserved: readSnapshot internally
previews the exact DepositPreauth {Account: company, Unauthorize: bob} plan,
removeIndividualApproval is the approval action, refuses stale/reused plans,
and never resubmits an uncertain transaction.

Session: createDemoEnvironment returns an opaque in-process handle (no seeds,
no signed blobs, not serializable/forgeable). Hold it in memory.

Required deps/config: Node >= 22; xrpl 5.3.0; dotenv 16.6.1;
.env XRPL_URL (official Devnet/Testnet WSS only), optional GATECHECK_NETWORK
(must match), optional GATECHECK_RUNTIME_DIR (journal + stored plans, gitignored).
Only official Devnet/Testnet WSS and matching network IDs accepted.
Amendments verified on the validated ledger: Credentials, DepositAuth, DepositPreauth.
